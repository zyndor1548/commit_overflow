## 1. What is FOSS?

FOSS stands for **Free and Open Source Software**. 

It represents a global movement and development methodology that has shaped the modern internet. Examples of open-source software include operating systems (Linux), programming languages (Python, JavaScript), development tools (Git, VS Code), and many applications used every day by millions of people.

### The Meaning of Free
> [!NOTE] 
> "Free" in FOSS refers to **freedom**, not necessarily price. (Think "free speech", not "free beer").

Users have the freedom to:
- **Use** the software for any purpose.
- **Study** how the program works and adapt it to their needs.
- **Modify** the software to improve it or fix bugs.
- **Share** and redistribute copies so you can help others.

### The Meaning of Open Source
"Open Source" means the source code—the instructions written by programmers—is available for people to inspect, modify, and redistribute under specific licenses (like MIT, GPL, or Apache).

## 2. How Does an Open-Source Project Work?

Open-source projects are highly collaborative. A single project can have contributors from different countries, backgrounds, and skill levels working together asynchronously through platforms like **GitHub** and **GitLab**.

### Key Roles in a Project

Every open-source community relies on different people playing different roles:

*   👑 **Maintainers**: The leaders and decision-makers. They are responsible for reviewing code, merging pull requests, and setting the direction of the project.
*   🤝 **Contributors**: People (like you!) who make changes, fix bugs, or add improvements to the project.
*   🎓 **Mentors**: Experienced contributors who help newcomers understand the codebase, review their work, and solve problems.
*   👥 **Users**: People who use the software. They play a critical role by reporting bugs, requesting new features, and providing feedback.

## 3. What Can You Contribute?

A common misconception is that you must be an expert programmer to contribute to open source. **This is false!** You don't necessarily have to write complex code to be a valuable contributor.

### Code Contributions
If you like writing code, you can contribute by:
*   🐛 **Fixing bugs:** Resolving issues reported by users.
*   ✨ **Adding features:** Building new functionality to improve the software.
*   🛠️ **Improving existing code:** Refactoring messy code to be cleaner and more efficient.
*   🧪 **Writing tests:** Creating automated tests to ensure the software doesn't break in the future.

### Non-Code Contributions
If you prefer not to code, or are just starting out, you can make huge impacts by:
*   📚 **Improving documentation:** Writing tutorials, updating README files, or clarifying setup instructions.
*   🎨 **Improving UI/UX:** Designing better interfaces or user experiences.
*   ✏️ **Fixing typos:** Correcting spelling or grammatical formatting errors.
*   🚨 **Reporting bugs:** Testing the software and writing detailed reports when things break.
*   ♿ **Improving accessibility:** Ensuring the software can be used by people with disabilities.
*   💡 **Adding examples:** Providing sample code or use cases for others to learn from.

> [!TIP]
> During **Commit Overflow**, your first job as a contributor is to act like a User and a QA Tester! You are expected to explore the provided software, find bugs or missing features, and **raise the issue yourself**. Once a mentor approves your issue, you get to fix it!
